01 — Why COBOL on Windows

Decades of business logic, now on the desktop.

Your COBOL was written to last. COBOL on Windows lets it keep running where your team already works — Windows laptops, servers and CI pipelines.

01

Native .exe and .dll

GnuCOBOL 3.2 with its own bundled GCC 13.1 compiles to standalone executables (cobc -x) or callable modules (cobc -m). No runtime server, no licence.

02

Copybooks as-is

COPY and REPLACING work unchanged, and so do CALLed subprograms sharing a record through a copy — exactly what the subroutine\ example does.

03

EXEC SQL over ODBC

GixSQL 1.0.20b preprocesses EXEC SQL for PostgreSQL, MySQL/MariaDB, SQLite and, through ODBC, anything with a driver: DB2 (shipped), Access, Excel, SQL Server.

04

A real IDE, a real debugger

VSCodium and SuperBOL Studio OSS: syntax highlighting, breakpoints and step-by-step debugging through gdb. Call the .dll from Java, C#, C/C++ or Python; build it in GitHub Actions or GitLab CI.

02 — Examples

03 — Mainframe map

Every host concept has a home.

What you used on z/OS, and what it becomes under COBOL on Windows.

On the mainframe On Windows
Load module → .exe (cobc -x) or .dll (cobc -m), CALLable from any language
JCL job step → PowerShell script, .cmd batch file or shell script
DD statement → DDNAME environment variable mapped to a file path
Sequential dataset → Fixed or variable-length record file
VSAM KSDS → ORGANIZATION INDEXED, on the bundled Berkeley DB ISAM
DB2 precompiler → gixpp, the GixSQL EXEC SQL preprocessor, then cobc — DB2 over its ODBC/CLI driver, shipped here
DCLGEN copybook → .cpy host-variable record, pulled in with EXEC SQL INCLUDE
ISPF edit, TSO → VSCodium + SuperBOL Studio OSS, with gdb breakpoints and step-by-step debugging
RETURN-CODE → Process exit code — %ERRORLEVEL% or $LASTEXITCODE
04 — Get started

Three steps to your first execution.

Windows 10 or later, x64 only at the moment. Nothing is compiled at install time and nothing is registered system-wide, so no administrator rights are needed — the one exception is the optional Excel/Access ODBC connector, installed only when the script itself runs elevated.

STEP 1

Install

.\install-cobol-on-win.ps1

Run it with powershell -ExecutionPolicy Bypass -File. Everything lands in C:\cobol-dev; add -InstallDir to put it elsewhere.
The script works on its own, whatever is not next to it is downloaded from the GitHub repository.

STEP 2

Open the IDE

C:\cobol-dev\CoBOL-Codium.cmd

Type COBOL in the Windows start menu, it will open VSCodium on the example project with hello-world.cob active. A desktop shortcut is created too.

STEP 3

Build and run

F7

COBOL: build and run. F9 builds a program containing EXEC SQL, F10 a CALLable .dll, F5 starts the debugger. Exit codes map directly to RETURN-CODE.
